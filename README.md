# Digital Momentum 
  
**كل أدوات نموّك الرقمي في مكان واحد**

## فكرة المشروع

Digital Momentum منصة لإدارة طلب خدمات التسويق عبر وسائل التواصل الاجتماعي من مكان واحد. تساعد العملاء على اكتشاف الخدمات، إنشاء الطلبات ومتابعتها، وإدارة الرصيد والمدفوعات، مع لوحة إدارية لمتابعة المستخدمين والطلبات ومراجعة الدفعات.

تجمع المنصة تجربة العميل والإدارة في واجهة عربية وإنجليزية تدعم اتجاهي العرض RTL وLTR.

## المشكلة

قد يضطر من يدير حضوره الرقمي إلى التعامل مع خدمات متعددة عبر مواقع ومحادثات ووسائل دفع متفرقة. ويصعب عندها معرفة الأسعار، تتبع حالة كل طلب، ومراجعة الرصيد وسجل المعاملات من مكان واحد.

## الحل

توفر Digital Momentum واجهة موحدة تتيح:

- استعراض الخدمات والبحث بينها ومعرفة الأسعار والحدود.
- تقديم طلب فردي أو مجموعة طلبات، ثم متابعة حالتها وسجلها.
- إدارة الرصيد وطلبات الإيداع وسجل المعاملات.
- التواصل مع الدعم عبر التذاكر ومتابعة الأخبار والأسئلة الشائعة.
- مراجعة الإدارة للمستخدمين والمدفوعات ومعلومات الخدمات والمزوّدين.

## أساسيات المنصة

- **العملاء:** إنشاء الطلبات، متابعة التنفيذ، مراجعة الرصيد والمعاملات، والتواصل مع الدعم.
- **الإدارة:** متابعة النشاط والمستخدمين، ومراجعة طلبات الدفع وإدارة معلومات الخدمات.
- **تجربة الاستخدام:** صفحات متجاوبة، لغتان، واتجاها عرض فاتح وداكن.
- **التقنية:** واجهة Next.js، وخادم FastAPI قابل للربط عبر واجهة API موثقة.

## السياسات والمبادئ

1. **الوضوح:** عرض حالة الطلب والدفع والتكلفة وسجل المعاملات بوضوح.
2. **حماية الحسابات والبيانات:** التحقق من صلاحيات المستخدم، وعدم إظهار بيانات العميل أو سجلاته لغير المخوّلين.
3. **سلامة المدفوعات:** لا يُعتمد الدفع الإلكتروني ولا يُضاف رصيد حقيقي إلا بعد التحقق من جهة الدفع على الخادم.
4. **المسؤولية:** استخدام الخدمات بما يتوافق مع القوانين وشروط المنصات ومزوّدي الخدمات، وعدم استخدامها للخداع أو انتحال الهوية أو الإضرار بالآخرين.
5. **الشفافية بشأن حالة المنتج:** توضيح الفرق بين بيانات المعاينة والعمليات الحقيقية، وعدم اعتبار بيانات العرض إثباتًا على تنفيذ خدمة فعلية.

## حالة المشروع

المشروع يتضمن واجهة تجريبية متكاملة نسبيًا، وخادم FastAPI أوليًا، وعقدًا مقترحًا لربط الواجهة بالخادم. وضع المعاينة يحفظ بياناته في المتصفح، وبعض الشاشات تعرض بيانات أو نتائج توضيحية. لذلك لا تعني الواجهة الحالية أن الدفع أو إرسال الطلبات إلى مزوّدين أو البريد أو أدوات المراقبة تعمل فعليًا.

قبل الإطلاق، يلزم استكمال الخادم وربطه بمزوّدين موثوقين، وتنفيذ المصادقة والصلاحيات والتحقق من المدفوعات، ثم اختبار تدفقات الطلبات والأرصدة والخصوصية في بيئة آمنة. راجع [توثيق الواجهة](frontend/README.md) و[عقد API](frontend/API.md) للتفاصيل.

## تشغيل نسخة التطوير

تتطلب الواجهة Node.js 22.12 أو أحدث وnpm. من جذر المشروع:

```powershell
npm ci --prefix frontend
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000). لتشغيل خادم FastAPI الأولي، اتبع التعليمات في [fastApi/README.md](fastApi/README.md).
