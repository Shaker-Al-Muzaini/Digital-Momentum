# واجهة SMM Panel

تطبيق React JavaScript مبني على Next.js App Router. يحتوي على 29 شاشة مستمدة من التصميمين، مع العربية والإنجليزية واتجاهي RTL/LTR والمظهر الفاتح والداكن. تتشارك الصفحات القوائم والنماذج والجداول وعميل HTTP. يستخدم الموقع مسارات عادية يمكن فتحها مباشرة أو تحديثها.

## التشغيل

استخدم Node.js 22.12 أو أحدث و npm. يمكن تشغيل الأوامر من جذر المشروع باستخدام `npm run dev`، أو من داخل مجلد frontend:

```bash
cd frontend
npm ci
cp .env.example .env.local
npm run dev
```

في Windows استخدم `copy .env.example .env.local` بدلاً من `cp`. بعد تثبيت الاعتماديات لأول مرة، يمكنك تشغيل التطبيق مباشرة من الجذر عبر `npm run dev`. افتح http://localhost:3000. لتجربة نسخة الإنتاج شغّل `npm run build` ثم `npm start`، وشغّل اختبارات المعاينة باستخدام `npm test` (من الجذر أو frontend).

## تجربة الحسابين

| الدور | البريد | كلمة المرور |
|---|---|---|
| العميل | demo@smm.app | demo1234 |
| المدير | admin@smm.app | demo1234 |

الوضع الافتراضي **demo**. تحفظ المعاينة الطلبات والرصيد والدفعات والتذاكر في sessionStorage داخل التبويب الحالي. تبقى البيانات عند تحديث الصفحة، وتنتهي عند إغلاق التبويب أو جلسة المتصفح؛ قد تستعيدها ميزة استعادة الجلسة في بعض المتصفحات. استخدم التبويب نفسه للتبديل بين العميل والمدير. سجّل دخول المدير ثم اعتمد تحويل العميل من صفحة الدفعات، وادخل كعميل لرؤية أثره على الرصيد. الحوالة تبقى قيد المراجعة إلى حين الاعتماد. بيانات المراقبة والمزودين أمثلة، ومولّد المحتوى يعرض نتيجة توضيحية. إرسال البريد، تحصيل المال، وتشغيل أدوات Linux تتطلب الخادم. لإعادة ضبط المعاينة امسح مفتاح sessionStorage المسمى smm-preview-session-v2.

## الصفحات

| القسم | المسارات |

| الموقع العام | /، /services، /pricing، /how، /api، /faq، /contact |
| الحساب | /auth/login، /auth/register، /auth/forgot |

تضم لوحة العميل طلباً فردياً وجماعياً، سجل الطلبات مع التصفية، دليل الخدمات مع البحث، حساب التكلفة، الدفع بالبطاقة أو طلب تحويل مع إيصال، سجل المعاملات، الإحالات، نسخ مفتاح API، الأخبار والتذاكر وتفضيلات الحساب. تعرض الإدارة ملخص النشاط والمستخدمين ومراجعة الدفعات وحالة المزودين والبروكسيات، وتوليد المحتوى ومراقبة الخادم.

## ربط FastAPI

اضبط القيم التالية في .env.local ثم أعد تشغيل Next.js (وأعد البناء عند تغيير وضع البيانات في الإنتاج).

```dotenv
NEXT_PUBLIC_DATA_MODE=api
FASTAPI_URL=http://127.0.0.1:8000/api/v1
```

داخل Docker Compose استبدل المضيف باسم خدمة FastAPI مثل http://api:8000/api/v1. يطلب المتصفح /backend/... من نفس الأصل، ثم يحوّل Next.js المسار إلى FASTAPI_URL. الواجهة تتوقع جلسة في Cookie يضبطها الخادم بمسار / ومن دون Domain داخلي. على الخادم التحقق من الجلسة ودور المدير وملكية السجلات، والتحقق من Origin لكل تعديل بحسب سياسة النشر. تتلقى الواجهة خطأ FastAPI من detail كنص أو قائمة أخطاء تحقق، وتعرض خيار إعادة المحاولة عند فشل القراءة.

الملف [API.md](API.md) يحدد العقد المقترح للنقاط والحقول. لم يُرفق مخطط OpenAPI لخادم قائم. طابق العقد معه عند الدمج، أو عدّل التحويل في lib/api.js. لا يحتاج وضع API إلى أي بيانات محلية للمعاينة. مثال /api/v2 الظاهر للمطورين في التصميم يخص واجهة عملاء SMM الخارجية، وهو مستقل عن واجهة التطبيق الداخلية.

## بنية المصدر

- app/ يعرّف مسارات الموقع والحساب واللوحة والتخطيطات.
- components/site/ يحتوي على الصفحة الرئيسية والتخطيط والصفحات العامة.
- components/panel/ يحتوي على شاشات الحساب والطلبات والفوترة والإدارة.
- components/shared.jsx يجمع تفضيلات اللغة والسمات وحالات الطلب والنماذج والجداول.
- lib/api.js هو نقطة الاتصال، وlib/demo.js بديل المعاينة، وlib/orders.js تحقق الطلبات.
- public/site.css وpublic/panel.css يحتويان على تنسيقات التصميمين الأصليين، مع إضافات التجاوب والحركة.

## التفاعلات التجريبية

إنشاء الطلب يعرض رسالة نجاح برقم الطلب ثم يفتح السجل. الطلبات الجديدة تنتقل من الانتظار إلى التنفيذ بعد 5 ثوانٍ، ثم تكتمل بعد 20 ثانية، مع تحديث السجل والإحصائيات كل ثانيتين. الدفع بالبطاقة يضيف رصيدًا تجريبيًا فقط؛ التحويل المحلي يحتاج اعتماد المدير في الجلسة نفسها. لا تُرسل أموال أو طلبات إلى أي جهة خارجية. رسائل النماذج تعرض نجاح العملية أو خطأ التحقق. إجماليات الإدارة محسوبة من معاملات الجلسة، ومولّد المحتوى يعرض قالبًا تجريبيًا حسب الموضوع واللغة.
